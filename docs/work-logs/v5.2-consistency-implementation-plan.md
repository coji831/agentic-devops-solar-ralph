## Executive Summary

**Problem:** Agents obey role constraints early in a session, then decay — they use forbidden tools, hallucinate tool access, bleed roles across agent switches, and skip reasoning in favor of raw execution. Root cause (Liu et al. 2023 "Lost in the Middle"): role instructions get pushed out of the attention sweet spot as context grows, and prompt-only rules are probabilistic.

**Solution:** Move enforcement from _prompts_ to _platform primitives_. Three levers, in order of leverage:

1. **Platform `tools:` frontmatter** — per-agent tool scoping enforced by VS Code before the model ever sees the tool (proven in the mandarin repo).
2. **The 2026 hook surface** — `PreToolUse` (block tool calls), `UserPromptSubmit` (re-inject instructions), `PreCompact` (export pinned state before truncation).
3. **`npx` install CLI** — one-line install (`npx @solar-ralph/cli install`), removing the human-in-the-loop prompt scaffold as the only path.

**Version:** v5.2.0 — minor (stays in the v5 line). New enforcement architecture layer + new install path, but no breaking change to existing target-repo scaffolds; all additions are opt-in via config toggles.

**Risk:** MEDIUM — additive hooks and declarative scoping are low-risk; the CLI touches the install path (highest-risk surface); the "Lite mode" decision affects the default scaffold.

| --- | ---------------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------- |

## 2. Phase Breakdown

### Phase 1 — Platform `tools:` scoping (static tool gate)

**Goal:** Every specialist gets an explicit `tools:` allowlist in `.agent.md` frontmatter; forbidden tools are never advertised, so hallucination (behavior #2) and most of tool-decay (behavior #1) are impossible.

**Changes:**

- Add `tools:` frontmatter to all 7 `template/.github/agents/*.agent.md`, matching the mandarin pattern:
  - `context-summarizer.agent.md` → `tools: [read, ...]` (only agent with `read`)
  - `data-collector`, `design-planning-architect`, `implementation-specialist`, `test-specialist`, `docs-curator`, `review-auditor` → no `read` (context arrives via digest)
  - `orchestration-governor.agent.md` → no write/edit tools (it only dispatches + writes ledger)
- Document the allowlist in `AGENTS.md` §3 as a `Tools` column (single source of truth).
- Sync `solar-install.prompt.md` + `solar-install-inventory.md` (installer-authoring invariant).

**Why platform scoping, not just prompts:** the mandarin repo (proven) demonstrates `tools:` is enforced by the harness before generation — the agent cannot even request a forbidden tool. This is the exact "dynamic tool scoping" the research recommended, with zero hook code.

**Effort:** Low. **Risk:** Low.

---

### Phase 2 — Pinned-state + instruction re-injection

**Goal:** Fix "lost middle" decay (the root cause behind behaviors #1, #3, #4) by keeping a compact role/state block near the generation point at all times.

**Changes:**

1. **`SessionStart` hook** (`state-pin.cjs`) — write `.github/.solar_state.json`: objective, active constraints, open tasks, current stage (~150–300 tokens). This is the "Pinned State" tier that survives compaction.
2. **`UserPromptSubmit` hook** (`preamble.cjs`) — on every user turn, return `additionalContext` with the compact role block (identity + stage + constraints). Lands near the generation point — the attention sweet spot.
3. **`PreCompact` hook** (part of `state-pin.cjs`) — refresh pinned state before VS Code truncates context, so constraints are never lost to summarization drift (fixes the "413 death spiral / implicit-contract loss" documented in `context-injection-and-token-runaway.md`).

**Gate:** behind `solar.config.json` → new `pinned_state` toggle (default `true`).

**Effort:** Low–Medium. **Risk:** Low. Token cost ~150/turn.

---

### Phase 3 — `PreToolUse` dynamic gate (stage + write-op guard)

**Goal:** Enforce plan-before-execute (behavior #4) and catch any tool call the static allowlist can't express (stage-dependent rules).

**Changes:**

1. **`pre-tool-use.cjs`** — new hook:
   - **Stage gate:** if the tool is a write-op (`edit/creat/insert/delet/writ/replac`) and the ledger stage is still `Scan` or `Plan`, return `permissionDecision: "deny"` + `systemMessage: "Plan stage not complete — dispatch Design Planning Architect first."`
   - **Write-op guard:** at `VERIFY` stage, keep the existing `ADVERSARIAL_VERIFY_REQUIRED` signal (moves from `PostToolUse` to `PreToolUse` for earlier interception).
2. **Exit-code-2 fallback:** if state is unparseable, exit `2` (blocking error shown to model).
3. Register in `hooks.json` alongside the existing `PostToolUse`.

**Note on v5.0.0 removal:** v5.0.0 removed `PreToolUse` for _token-efficiency_ reasons (baton enrichment, signal routing). This reintroduction is for a _different purpose_ — the `permissionDecision` tool gate. It is deliberately minimal: no baton fields, no telemetry, no tracker.

**Gate:** `tool_gate` toggle (default `true`).

**Effort:** Medium. **Risk:** Medium (behavior-changing — a denied write-op must degrade gracefully).

---

### Phase 4 — `npx` install CLI

**Goal:** True one-line install, matching DeepSeek Harness (`npx @deepseek-ai/dsh web`) and Claude Code patterns.

**Changes:**

1. **New `cli/` package** (`@solar-ralph/cli`) — thin Node CLI, zero runtime deps:
   - `npx @solar-ralph/cli install` — copy `template/` → target `.github/`, run `[FILL IN]` substitution, prompt interactively for stack/agent names (or `--stack=… --non-interactive`).
   - `npx @solar-ralph/cli` (no args) — print usage + detect-repo summary.
   - `npx @solar-ralph/cli update` — re-sync scaffold from a newer version.
2. **Single source of truth:** the CLI reads `solar-install-inventory.md` directly (parse `## INV:<slug>` sections) so prompt-scaffold and CLI never diverge.
3. **Keep `solar-install.prompt.md`** as the fallback for no-Node / restricted-MCP environments.

**Effort:** Medium–High. **Risk:** Medium (install path is the adoption-critical surface).

---

### Phase 5 — Delegation Map + role preamble (Governor readability + behavior #3)

**Goal:** Borrow the mandarin repo's proven readability win and make role boundaries explicit per dispatch.

**Changes:**

1. **`orchestration-governor.agent.md`** — add a **Delegation Map table** ("when user asks to X → route to Agent Y") as the primary routing reference, keeping the stage loop as the execution engine.
2. **`solar.prompt.md` §3c** — one line hardening: every dispatch already repeats the role preamble; make it explicit that _raw conversation is never passed — only `{task_id, refs[]}` + digest._
3. **`SubagentStop` hook** (`subagent-check.cjs`) — verify the subagent produced its declared artifact; non-blocking warning if missing.

**Effort:** Low. **Risk:** Low.

---

### Phase 6 (medium-term) — Plugin contract / registry auto-discovery

**Goal:** Borrow DeepSeek Harness's "everything is a plugin" convention so the registry auto-populates from the filesystem.

**Deferred from v5.2** — requires a plugin manifest spec + installer support. Track as `TD-5-1` in TODOs.md. Do **not** adopt DeepSeek's runtime (SOLAR's no-runtime, `.github/`-only design is the differentiator).

## 5. Migration & Breaking Changes

- **Behavior change (opt-in):** target repos that pinned the old 1-hook `hooks.json` will now load 5 hooks. All new hooks are passive when their toggle is `false`; the only behavior-changing hook is `pre-tool-use.cjs` (P3). Migration note: if a repo sees unexpected write-op denials, set `tool_gate: false`.
- **Non-breaking:** `tools:` frontmatter is additive (agents without it fall back to harness defaults, but the v5.2 template ships it on all agents).
- **CLI** is a new path — the prompt-scaffold path remains valid and must produce identical output (enforced by the shared inventory file).

## 7. Risks & Open Questions

**Risks:**

- **P3 behavior change** is the only one that can break an in-flight task — a denied write-op must surface a clear `systemMessage`, not a silent stop.
- **P4 CLI** has the classic two-sources-of-truth risk — mitigated by making the CLI parse `solar-install-inventory.md` directly.
- **Token cost** of per-turn re-injection (~150/turn) — acceptable at DeepSeek V4 Flash prices, but should be measured.

**Open questions (carried from deep-dive):**

1. Tool allowlist: `AGENTS.md` (human-readable) vs. `tools_allowlist.json` (machine)? — _recommend: keep in `AGENTS.md` `Tools` column + `tools:` frontmatter; the `PreToolUse` gate reads only the ledger stage, not a JSON allowlist._
2. Preamble frequency: every turn vs. after compaction vs. on stage change? — _recommend: every turn while cheap; add stage-change trigger if cost matters._
3. Should the gate also auto-approve safe ops (invert `human_approval` friction)? — _recommend: no for v5.2; keep `human_approval` as-is._
4. ~~Version number~~ — resolved: staying in v5 as **v5.2.0** (minor). The enforcement layer is additive and opt-in, so no major bump.
